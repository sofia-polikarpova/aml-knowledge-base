В задаче AML‑анализа важно, чтобы модель:

- не была жёстко привязана к одному блокчейну;
- могла быть перенесена между сетями (Ethereum, BSC, Tron, Bitcoin и др.);
- использовала признаки, которые **доступны или вычислимы практически в любом блокчейне**.

Поэтому в рамках дипломной работы выделяется **универсальный (базовый) набор признаков**, применимый к большинству блокчейн‑графов, поверх которого могут добавляться chain‑specific расширения.
### Принципы отбора универсальных признаков

При формировании набора признаков использовались следующие критерии:

1. **Доступность** — признак можно получить из публичного блокчейн‑леджера.
2. **Независимость от платформы** — не привязан к конкретной виртуальной машине или стандарту токенов.
3. **Информативность для AML** — отражает поведение, активность или финансовые характеристики.
4. **Агрегируемость** — может быть вычислен на основе транзакций за период.
### Базовые сущности данных

Для большинства блокчейнов можно выделить следующие сущности:

- **Address / Account** — узел графа;
- **Transaction** — ребро графа;
- **Timestamp / Block height** — временная ось.

Соответственно, признаки делятся на **node‑features**, **edge‑features** и **temporal features**.

**Универсальные признаки узлов (Node Features)**

**1. Идентификационные признаки**

- address_id — уникальный идентификатор адреса;
- is_contract — флаг смарт‑контракта (если применимо).

**2. Финансовые признаки**

Признаки, вычисляемые на основе входящих и исходящих транзакций:

- total_in_volume — суммарный входящий объём;
- total_out_volume — суммарный исходящий объём;
- net_flow — разница входящего и исходящего объёма;
- avg_tx_amount — средняя сумма транзакции;
- max_tx_amount — максимальная сумма транзакции.

Применимы как для account‑based, так и для UTXO‑based моделей (через агрегацию).

**3. Поведенческие признаки**

- tx_count — общее число транзакций;
- in_tx_count — число входящих транзакций;
- out_tx_count — число исходящих транзакций;
- unique_counterparties — количество уникальных контрагентов;
- activity_ratio — отношение входящих к исходящим транзакциям.

**4. Временные признаки**

- first_tx_time — время первой транзакции;
- last_tx_time — время последней транзакции;
- address_age — возраст адреса;
- avg_inter_tx_time — средний интервал между транзакциями;
- tx_frequency — частота активности.

**5. Структурные графовые признаки**

Признаки, извлекаемые из структуры графа:

- in_degree — число входящих рёбер;
- out_degree — число исходящих рёбер;
- total_degree — общее число связей;
- pagerank — важность узла в графе;
- clustering_coefficient — локальная плотность связей.

**6. Репутационные и семантические признаки**

Минимально универсальный набор:

- entity_type — тип сущности (User / Exchange / Mixer / Contract / Unknown);
- known_service_flag — принадлежность к известному сервису;
- risk_hint — априорный индикатор риска (если доступен).

Даже при отсутствии полной разметки тип сущности может быть задан частично.

**Универсальные признаки рёбер (Edge Features)**

Рёбра соответствуют транзакциям между адресами.

**Базовый набор:**

- amount — сумма транзакции;
- direction — направление перевода;
- timestamp — время транзакции;
- tx_type — тип операции (transfer / contract call);
- interaction_count — число повторных взаимодействий между узлами.

**Универсальные временные представления**

Для большинства моделей возможно использование:

- агрегации по временным окнам;
- sliding window;
- snapshot‑графов.

Это позволяет учитывать динамику без жёсткой привязки к конкретному блокчейну.

**Chain‑specific расширения (необязательные)**

Поверх универсального набора могут добавляться:

- gas‑признаки;
- token‑specific статистики (ERC‑20, TRC‑20);
- UTXO‑характеристики (Bitcoin‑like).

Эти признаки **не входят** в базовый универсальный набор.
### Связь с SemiGNN и HAN

Универсальный набор признаков:

- формирует вход для node‑embeddings;
- используется attention‑механизмами для вычисления важности узлов;
- позволяет переносить модель между блокчейнами без изменения архитектуры.
### Вывод

Выделение универсального набора признаков позволяет:

- строить переносимые AML‑модели;
- снижать зависимость от конкретного блокчейна;
- упростить экспериментальную часть дипломной работы.

Такой подход делает модель более устойчивой и практически применимой в реальных AML‑сценариях.
