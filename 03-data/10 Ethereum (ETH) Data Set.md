**Ethereum (ETH) — обзор датасета и признаков адресов для AML**

В рамках дипломной работы Ethereum рассматривается как основной блокчейн для практических экспериментов. Цель анализа открытого датасета **Ethereum Fraud Detection Dataset** — не использование всех признаков напрямую, а:

- понять, **какими признаками может обладать адрес в сети Ethereum**;
- выделить информативные группы признаков для AML-задачи;
- сопоставить их с ранее сформированным **универсальным набором признаков**;
- подчерпнуть идеи для feature engineering при работе с реальными данными.

**Датасет:** https://www.kaggle.com/datasets/vagifa/ethereum-frauddetection-dataset

### Общая информация о датасете

Датасет содержит агрегированные признаки Ethereum-адресов и бинарную метку:

- 0 — легитимный адрес
- 1 — мошеннический адрес

Признаки рассчитаны на основе истории транзакций адреса и отражают:

- финансовую активность,
- поведенческие паттерны,
- взаимодействия с контрактами и токенами.

Датасет носит исследовательский характер и не является полностью репрезентативным для production-сценариев.

### Основные группы признаков в датасете

**1. Базовые идентификаторы**

- Address — Ethereum-адрес
- FLAG — метка мошенничества

Эти поля не используются как входные признаки модели, но необходимы для обучения и оценки.

**2. Финансовые признаки (ETH)**

Отражают движение **нативной валюты Ethereum (ETH)**:

```python
Avg min between sent tx       #средний интервал между исходящими транзакциями
Avg min between received tx   #средний интервал между входящими транзакциями
Time Diff between first and last (Mins) #период активности адреса
Sent tnx                      #количество исходящих транзакций
Received tnx                  #количество входящих транзакций
Total Ether Sent              #суммарно отправлено ETH
Total Ether Received          #суммарно получено ETH
Total Ether Balance           #итоговый баланс
```


Эти признаки соответствуют универсальной группе **финансовых и временных node-features**.

**3. Поведенческие признаки**

Признаки, описывающие активность адреса:

```python
Number of Created Contracts      #количество созданных контрактов
Unique Sent To Addresses         #число уникальных получателей
Unique Received From Addresses   #число уникальных отправителей
Min/Max/Avg value sent           #статистики по суммам
Min/Max/Avg value received.
```

Эти признаки отражают паттерны поведения, важные для выявления аномалий.

**4. Признаки взаимодействия со смарт-контрактами**

Ethereum поддерживает смарт-контракты, поэтому в датасете присутствуют признаки:

```python
Total transactions (including contract calls);
Contract Interaction Count (неявно);
Number of Created Contracts.
```

В AML-контексте активное использование контрактов может быть как легитимным (DeFi), так и рискованным.

### ERC-20

**Что такое ERC-20**

**ERC-20** — стандарт токенов в сети Ethereum. В отличие от нативной валюты ETH:

- токены ERC-20 существуют как смарт-контракты;
- переводы токенов реализуются через вызовы функций контракта;
- один адрес может взаимодействовать с множеством токенов.

Примеры ERC-20 токенов:

- USDT, USDC
- PEPE
- SHIB

**ERC-20 признаки в датасете**

В датасете представлены отдельные группы признаков:

```python
ERC20 Total Ether Received
ERC20 Total Ether Sent
ERC20 Total Ether Balance
ERC20 Unique Sent Token Name
ERC20 Unique Received Token Name
ERC20 Most Sent Token Type
ERC20 Most Received Token Type
```

Эти признаки описывают **ненативные активы**, которыми оперирует адрес.

**Какие признаки НЕ стоит использовать напрямую**

Несмотря на богатство датасета, не все признаки целесообразно переносить:

- сильно коррелирующие признаки;
- признаки, зависящие от конкретного временного окна;
- искусственно агрегированные статистики;
- признаки, специфичные для конкретной разметки датасета.

В дипломной работе эти признаки используются **как источник идей**, а не как готовый feature set.

Из анализа датасета Ethereum можно выделить:

- важность **временных интервалов активности**;
- значимость **уникальных контрагентов**;
- отдельную роль **ERC-20 активности**;
- необходимость разделения нативных и ненативных активов;
- полезность агрегированных статистик для node-features.

### Связь с универсальным набором признаков

Большинство признаков датасета укладываются в ранее выделенные группы:

- финансовые
- поведенческие
- временные
- семантические

Это подтверждает корректность выбранного универсального подхода и возможность адаптации моделей (SemiGNN, HAN) под Ethereum.

### Вывод

Ethereum-датасет демонстрирует, насколько богатыми могут быть признаки одного адреса. Однако для переносимой AML-модели важно не использовать весь набор напрямую, а абстрагировать ключевые идеи, применимые к любому блокчейну.
