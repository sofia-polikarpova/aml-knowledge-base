Для обучения и применения графовой нейросети (GNN) в задаче AML необходимо сформировать **структурированный набор признаков**, описывающих поведение адресов и транзакций в сети Ethereum.

Особенность задачи заключается в том, что:

- Ethereum является **сложным блокчейном** (смарт-контракты, токены, DeFi);
- при этом многие признаки концептуально совпадают с Bitcoin;

поэтому разумная стратегия — **начать с Bitcoin-подобного базового набора**, а затем расширить его Ethereum-специфичными признаками.

### Общий подход к формированию признаков

Признаки формируются на уровне **графа транзакций**:

- узлы (nodes) — адреса / сущности;
- рёбра (edges) — транзакции между адресами.

Признаки делятся на:

- **Node features** — агрегированная характеристика адреса;
- **Edge features** — характеристики транзакций;
- **Temporal features** — временная динамика.

### Базовый набор (Bitcoin-подобный, минимально необходимый)

Этот набор применим как к Bitcoin, так и к Ethereum, и служит основой для построения GNN.

1. **Node features (адрес)**

```python
node_features_base = [
    'tx_count',                 # общее число транзакций
    'in_tx_count',              # входящие транзакции
    'out_tx_count',             # исходящие транзакции
    'total_in_volume',          # суммарно получено
    'total_out_volume',         # суммарно отправлено
    'net_flow',                 # вход - выход
    'unique_senders',           # уникальные отправители
    'unique_receivers',         # уникальные получатели
    'address_age',              # возраст адреса
    'avg_inter_tx_time',        # средний интервал между транзакциями
]
```

Этот набор:

- прост в реализации;
- не зависит от смарт-контрактов;
- полностью совместим с SemiGNN / HAN.

2. **Графовые структурные признаки**

Из структуры графа вычисляются дополнительные признаки:

```python
graph_features = [
    'in_degree',
    'out_degree',
    'total_degree',
    'pagerank',
    'betweenness_centrality',
]
```

 Эти признаки усиливают внимание модели к "центральным" узлам.

3. **Edge features (транзакции)**

```python
edge_features_base = [
    'amount',                   # сумма транзакции
    'timestamp',                # время
    'direction',                # направление
    'tx_frequency_pair',        # частота взаимодействия пары адресов
]
```

При невозможности явного использования edge-features они агрегируются в node-features.

### Расширение под Ethereum (ETH-specific)

После построения базового набора добавляются Ethereum-специфичные признаки.

**1. Признаки смарт-контрактов**

```python
eth_contract_features = [
    'is_contract',              # адрес является контрактом
    'contract_interaction_count',
    'created_contracts_count',
]
```

**2. ERC-20 активность**

ERC-20 — стандарт ненативных токенов Ethereum.

```python
erc20_features = [
    'erc20_tx_count',
    'erc20_total_sent',
    'erc20_total_received',
    'erc20_unique_tokens_sent',
    'erc20_unique_tokens_received',
]
```

Эти признаки отражают взаимодействие с токенами (USDT, PEPE и др.).

**3. Семантические и репутационные признаки**

```python
semantic_features = [
    'entity_type',              # User / CEX / DEX / Mixer / Contract
    'known_service_flag',
    'risk_hint',
]
```
 Эти признаки напрямую влияют на attention и "важность" узлов.

### Итоговая структура признаков

```
node_features = (node_features_base + graph_features + eth_contract_features + 
+ erc20_features + semantic_features)
```

Edge-features используются напрямую либо агрегируются.

**Почему разумно начинать с Bitcoin-логики**

- Bitcoin имеет простую транзакционную модель;
- легче отладить pipeline;
- проще интерпретировать attention;

Ethereum-специфика добавляется постепенно.

Такой подход снижает риск и упрощает экспериментальную часть диплома.

### Связь с моделью

Сформированный набор признаков:

- используется как вход в embedding-слои GNN;
- определяет вычисление attention-весов;
- позволяет адаптировать SemiGNN / HAN под Ethereum.

### Вывод

Построение набора признаков для Ethereum-AML целесообразно начинать с универсального Bitcoin-подобного базиса, постепенно расширяя его Ethereum-специфичными характеристиками.

Такой подход обеспечивает баланс между сложностью реализации и информативностью модели.
