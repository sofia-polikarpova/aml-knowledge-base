Данная заметка служит **введением в тему графовых нейронных сетей (GNN)** в контексте задачи Anti‑Money Laundering (AML) и блокчейн‑анализа. Здесь фиксируются базовые понятия, типы графов и представления данных, с которыми далее работают более сложные модели (GAT, HAN, SemiGNN).

### Граф как форма представления данных

Граф — это структура данных вида:

- **V (vertices / nodes)** — узлы;
- **E (edges)** — рёбра;
- **X_v, X_e** — признаки узлов и рёбер.

В задаче AML:

- узлы — это **блокчейн‑адреса**;
- рёбра — **транзакции между адресами**;
- признаки — числовые и категориальные характеристики активности.

### Типы графов, используемые в AML-задачах

1. **Transaction graph**

Классическое представление:

- узел = адрес;
- ориентированное ребро = транзакция from → to;
- признаки ребра: сумма, время, тип транзакции.

Используется для:

- анализа потоков средств;
- поиска цепочек переводов;
- выявления подозрительных паттернов.

2. **Temporal graph**

Граф с учётом временной динамики:

- рёбра упорядочены по времени;
- возможны временные срезы или окна.

Важно для AML, так как:

- отмывание средств — процесс во времени;
- паттерны могут быть краткоживущими.

3. **Heterogeneous graph**

Гетерогенный граф содержит разные типы узлов и/или рёбер.

Для блокчейна:

- типы узлов: EOA, CEX, DEX, mixer, smart contract;
- типы рёбер: transfer, contract call, token transfer.

Такое представление необходимо для учёта **разного влияния узлов на репутацию**.

4. **Multi-view graph**

Multi-view подход предполагает наличие нескольких графов (view), построенных над одним и тем же набором узлов, но с разной семантикой:

- transaction-based view;
- temporal view;
- value-based view.

Каждый view подчёркивает отдельный аспект поведения адреса.

### Почему нужны GNN

Классические ML-модели:

- не используют структуру графа;
- требуют ручной агрегации признаков.

GNN позволяют:

- автоматически агрегировать информацию от соседей;
- учитывать как локальные, так и глобальные связи;
- работать с частично размеченными данными.

### Базовая идея GNN (message passing)

Большинство GNN основаны на парадигме **message passing**:

- узел получает сообщения от соседей;
- сообщения агрегируются;
- формируется новое представление узла.

Общая формула:
```
h_v^{(k+1)} = UPDATE(h_v^{(k)}, AGGREGATE_{u ∈ N(v)}(h_u^{(k)}) )
```

## Простые GNN, применимые для real-time AML

В AML-задачах, особенно в сценариях оценки адресов «на лету», важна не только точность модели,  но и скорость inference.
### 1. Graph Convolutional Network (GCN)

**Идея:**  

GCN агрегирует признаки соседних узлов с помощью нормализованного усреднения.

**Преимущества:**

- простая архитектура;
- низкая вычислительная сложность;
- быстрая инференс-фаза.

**Ограничения:**

- все соседи считаются одинаково важными;
- плохо работает с динамическими графами;
- не учитывает типы узлов (CEX / DEX / mixer).

**Вывод:**  

GCN может использоваться как baseline для AML, но слабо отражает сложную структуру блокчейна.
### 2. GraphSAGE

**Идея:**  

GraphSAGE обучает функцию агрегации соседей, что позволяет делать **индуктивные предсказания** для новых узлов.

**Почему важно для блокчейна:**

- адреса появляются постоянно;
- нет необходимости пересчитывать весь граф.

**Преимущества:**

- подходит для online inference;
- масштабируем;
- используется в real-time системах.

**Ограничения:**

- не учитывает важность разных соседей;
- не работает с гетерогенными типами узлов.
### 3. FastGCN / Cluster-GCN

**Идея:**  

Оптимизация GCN за счёт семплирования узлов или кластеризации графа.

**Плюсы:**

- ускорение обучения и inference;
- масштабируемость.

**Минусы:**

- потеря части структурной информации;
- сложнее в реализации.
### Итог для AML-задачи

Простые GNN:

- подходят как baseline;
- потенциально применимы в real-time сценариях;
- но не учитывают разную «важность» узлов и рёбер.

Это ограничение естественным образом приводит к использованию attention-механизмов (GAT, HAN, Dual Attention, SemiGNN).
### Роль GNN в дипломной работе

Данная заметка используется как:

- концептуальное введение;
- описание типов графов, используемых далее;
- база для понимания GAT, HAN и SemiGNN.
