### Цель эксперимента

На данном этапе была реализована базовая GCN-модель для выявления мошеннических транзакций в графе Bitcoin (Elliptic dataset).  
  
Задачи этапа:  
- построить граф транзакций  
- подготовить признаки и метки  
- обучить двухслойную GCN  
- компенсировать классовый дисбаланс  
- получить baseline-результаты  
- оценить качество выявления illicit-транзакций  
  
В работе использовался подграф из 3000 узлов. Это было сделано для того, чтобы уместить эксперимент в доступные вычислительные ресурсы и стабильно запускать обучение и сравнение моделей. Использование подграфа позволяет ускорить эксперименты, но влияет на итоговое качество: модель обучается на более ограниченном локальном контексте, поэтому метрики становятся чувствительнее к выбору порога и к структуре конкретного фрагмента графа.

### Предобработка

1. Замена inf → nan
2. Замена nan → 0
3. Нормализация StandardScaler
4. Добавление class weights

```
weight_illicit = 1 / num_illicit
weight_licit   = 1 / num_licit
```

Class weights были использованы для того, чтобы модель не смещалась в сторону majority-класса. Однако в этой задаче не менее важен threshold: именно он определяет баланс между recall и количеством false positives. При слишком низком threshold модель начинает помечать слишком много узлов как fraud, а при слишком высоком — пропускает часть illicit-адресов.

### Архитектура модели
```
GCN(
  (conv1): GCNConv(165, 64)
  (conv2): GCNConv(64, 2)
)
```

**Параметры:**
- lr = 0.001
- weight_decay = 5e-4
- 80 эпох

### Интерпретация

**Recall (Illicit) = 0.7759**
  
Модель находит около 78% мошеннических транзакций. Это хороший результат для AML-задачи.  
  
**Precision (Illicit) = 0.9574**
  
Среди найденных мошеннических транзакций почти все действительно являются мошенническими. Ложноположительных срабатываний всего 2, то есть модель стала очень точной.  
  
**Accuracy = 0.975**
  
Метрика высокая, но сама по себе не является основной из-за дисбаланса классов. Для этой задачи гораздо важнее сочетание precision, recall и F1-score.  
  
Особенно важно, что итоговый threshold оказался равен 0.95. Это значит, что модель стала более консервативной и помечает узел как illicit только при высокой уверенности. В результате резко снизилось число false positives, а качество предсказаний стало более практичным для AML-сценария.

### Вывод

GCN демонстрирует:  
- высокую чувствительность к illicit-паттернам  
- способность использовать структуру графа  
- эффективность в задачах AML  
  
Однако:  
- качество сильно зависит от выбранного threshold  
- при работе с подграфом модель становится чувствительнее к локальной структуре данных  
- для этой задачи особенно важно контролировать false positives, а не только максимизировать recall

### Научное значение

Этот этап:  
- подтверждает применимость GNN для AML  
- служит baseline для сравнения  
- показывает, что графовая структура содержит информативные сигналы
