### 1. Постановка задачи

Цель этапа — исследовать применение архитектуры **HAN (Heterogeneous Attention Network)** для задачи обнаружения мошеннических транзакций в графе Elliptic.

Задача формулируется как **классификация узлов (node classification)** в графе транзакций.

**Основная метрика:**

**PR-AUC (Precision–Recall AUC)**, поскольку задача характеризуется **сильным дисбалансом классов**, где мошеннические транзакции составляют меньшую часть данных.

**Дополнительные метрики:**
 • F1-score для класса fraud
 • Precision
 • Recall
 • Accuracy

**Гипотезы исследования**
 1. Архитектура **HAN** может эффективно использовать структурную информацию графа.
 2. Механизм **attention** способен улучшить выявление мошеннических транзакций.
 3. Обучение на **полном графе** позволяет извлекать более сложные структурные зависимости.

### 2. Особенность представления графа

Изначально датасет **Elliptic** представляет собой **гомогенный граф транзакций**, где:
 • все узлы имеют один тип — transaction
 • все рёбра имеют один тип связи

Для применения архитектуры **HAN** была сформирована **гетерогенная структура графа**.

Созданное представление включало:
 • тип узлов: tx (transactions)
 • тип отношения: interact
 • контейнер данных **HeteroData** из библиотеки PyTorch Geometric

Таким образом, **гетерогенность графа не является исходным свойством данных**, а была введена на этапе моделирования.

Это было сделано для:
 • использования архитектуры **HANConv**
 • анализа влияния **attention-механизма**
 • сопоставления результатов с моделью **GAT**

Этот факт необходимо учитывать при интерпретации результатов.

### 3. Подготовка данных

**3.1 Исходные характеристики датасета**

Датасет **Elliptic Bitcoin Dataset** содержит:
 • **203 769 транзакций (узлов)**
 • **234 355 рёбер**
 • **165 числовых признаков транзакций**

Каждый узел представляет отдельную транзакцию в сети Bitcoin.

**Классы транзакций**
 • **0** — licit (легитимная транзакция)
 • **1** — illicit (мошенническая транзакция)
 • **unknown** — отсутствует разметка

**3.2 Подготовка признаков**

На этапе предобработки выполнялись следующие шаги:
 1. Загрузка таблицы признаков транзакций.
 2. Удаление идентификатора транзакции из набора признаков.
 3. Замена пропущенных значений.
 4. Нормализация признаков с использованием **StandardScaler**.
 5. Преобразование данных в **тензоры PyTorch**.

  **3.3 Использование полного графа**
  
В финальной версии эксперимента модель обучалась на **полном графе транзакций**.

Особенности постановки:
 • используются **все 203 769 узлов**
 • структура графа сохраняется полностью
 • обучение выполняется **только на размеченных узлах**

Количество размеченных узлов: **46 564**

Неразмеченные узлы используются для **распространения информации по графу**, что соответствует постановке **semi-supervised learning**.

### 4. Архитектура модели

Модель построена на основе слоя **HANConv** из библиотеки **PyTorch Geometric**.

Архитектура включает следующие компоненты:

1. HANConv слой
Выполняет агрегацию информации от соседних узлов с использованием **механизма внимания**.

2. Функция активации
Используется **ReLU**, добавляющая нелинейность в модель.

3. Линейный классификатор
Преобразует скрытое представление узла в вероятности классов.

**Параметры модели:**
 • входная размерность признаков: **165**
 • скрытая размерность: **128**
 • число attention-голов: **4**
 • dropout: **0.5**
 • выходная размерность: **2 класса**

### 5. Процесс обучения

Обучение модели выполнялось со следующими параметрами:
 • **оптимизатор:** Adam
 • **learning rate:** 0.005
 • **weight decay:** 5e-4
 • **число эпох:** 50

Для компенсации дисбаланса классов использовалась функция потерь **Weighted Cross Entropy**

Вес класса мошенничества увеличивался пропорционально его доле в обучающей выборке.

Функция потерь вычислялась **только на размеченных узлах**.

### 6. Результаты модели

После обучения на полном графе были получены следующие результаты.

**Основные метрики:**

- **PR-AUC:** 0.681
- **F1-score (fraud):** 0.60

**Classification Report**

**Класс 0 (licit)**
 • Precision: **0.97**
 • Recall: **0.93**
 • F1-score: **0.95**

**Класс 1 (fraud)**
 • Precision: **0.52**
 • Recall: **0.70**
 • F1-score: **0.60**

**Accuracy**: 0.91

### 7. Анализ результатов

Модель **HAN** продемонстрировала высокий показатель **recall для класса мошенничества (0.70)**.

Это означает, что модель способна обнаруживать значительную долю мошеннических транзакций.

Высокий recall является важным свойством для задач **fraud detection**, поскольку пропуск мошеннических операций может приводить к значительным финансовым потерям.

При этом **precision для класса fraud составляет 0.52**, что указывает на наличие ложных срабатываний.

Тем не менее итоговый **F1-score (0.60)** демонстрирует хороший баланс между точностью и полнотой.

Показатель **PR-AUC = 0.681** свидетельствует о хорошем качестве **ранжирования транзакций по вероятности мошенничества**.

### 8. Итоговые выводы этапа

 1. Архитектура **HAN** способна эффективно использовать структурную информацию графа транзакций.

 2. Обучение на **полном графе** существенно улучшило качество модели.

 3. Модель демонстрирует **высокий recall для мошеннических транзакций**, что критически важно для задач fraud detection.

 4. Полученный **F1-score (0.60)** является высоким показателем для данной задачи.

 5. Гетерогенность графа была сформирована **на этапе моделирования** и использовалась для применения архитектуры HAN.

Полученные результаты показывают, что модель **HAN является эффективным инструментом** для обнаружения мошеннических транзакций в графе Elliptic.
