### 1. Постановка задачи

Цель этапа — исследовать применение архитектуры HAN (Heterogeneous Attention Network) для задачи обнаружения мошеннических транзакций в графе Elliptic.

Основная метрика: **PR-AUC**, так как задача характеризуется сильным дисбалансом классов.

Гипотезы:
 1. HAN превосходит базовые GNN по качеству ранжирования.
 2. Увеличение глубины модели может улучшить извлечение структурных зависимостей.
 3. Focal Loss может повысить качество за счёт фокусировки на сложных примерах.
 
### 2. Особенность представления графа

Изначально датасет Elliptic представляет собой **гомогенный граф транзакций**, где:
 • все узлы имеют один тип (transaction),
 • все рёбра имеют один тип связи.

Для применения архитектуры HAN была искусственно сконструирована гетерогенная структура.

Созданное представление включало:
 • тип узлов: tx (транзакции);
 • введённые типы отношений (meta-path логика);
 • гетерогенный контейнер данных (HeteroData).

Таким образом, свойство гетерогенности **не является исходным свойством данных**, а было введено на этапе моделирования для:
 • расширения архитектурных возможностей;
 • анализа влияния attention-механизмов в гетерогенной постановке;
 • сопоставления с GAT.

Это важно зафиксировать при интерпретации результатов.

### 3. Подготовка данных

**3.1 Исходные характеристики датасета:**
 • 203 769 транзакций
 • 234 355 рёбер
 • 167 столбцов признаков (1 id + 166 числовых признаков)

**3.2 Очистка разметки**
Удалены транзакции с меткой unknown.

После фильтрации:
 • 46 564 размеченных узла
 • 36 624 рёбер между размеченными узлами

Важно: рёбра сохранялись только если **оба узла присутствуют в подграфе**.

### 4. Проблемы, выявленные в ходе работы

**4.1 KeyError при построении edge_index**

Причина: рёбра ссылались на узлы, отсутствующие после фильтрации features.

Решение:
 • синхронизация множества узлов;
 • строгая фильтрация edges по обновлённому множеству id.

**4.2 Неконсистентность размеров подграфа**

В ряде запусков размер графа менялся (18k узлов вместо 46k).
Причина:
 • повторная фильтрация без перезапуска kernel;
 • частичная загрузка данных.

Решение:
 • полный Restart Runtime;
 • последовательный запуск программы сверху вниз.

Вывод: для корректного сравнения моделей необходимо фиксировать идентичный подграф.

### 5. Архитектурные эксперименты

**5.1 1-layer HAN**

Параметры:
 • hidden = 128
 • heads = 4
 • dropout = 0.5

Результат:
 • PR-AUC ≈ 0.47
 • F1 fraud ≈ 0.33

Модель показала наилучший стабильный результат.

**5.2 2-layer HAN**

Добавление второго слоя привело к:
 • снижению PR-AUC;
 • ухудшению F1.

Интерпретация: эффект oversmoothing в условиях слабосвязного графа.

**Вывод**: для Elliptic оптимальна неглубокая архитектура.

### 6. Эксперименты с функциями потерь

**6.1 Weighted Cross Entropy**

Компенсация дисбаланса классов через веса.

Результат:
 • PR-AUC ≈ 0.47

**6.2 Focal Loss**

Параметры:
 • alpha = 0.75;
 • gamma = 2.0.

Результат на полном графе:
 • PR-AUC = 0.4615;
 • F1 fraud = 0.3393.

Интерпретация: Focal Loss не улучшил качество ранжирования.
Ограничение качества определяется структурой графа, а не функцией потерь.

### 7. Итоговые выводы этапа
 1. Качество модели ограничено топологией Elliptic.
 2. Увеличение глубины ухудшает результат.
 3. Focal Loss не даёт прироста PR-AUC.
 4. Лучший воспроизводимый результат: 1-layer HAN + Weighted CE.
 5. Гетерогенность графа является результатом моделирования, а не исходным свойством данных.
